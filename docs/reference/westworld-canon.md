写内容包时的事实底本。只写能撑起一场戏的东西，不写剧情。

> **核验状态**：本文写作环境无外网（只有 npm/PyPI 镜像可达，Wikipedia / Fandom / HBO 均不可访问），条目依据既有知识整理，**未能逐条抓取页面复核**。拿不准的细节就地标「未核实」，文末链接为条目主页，使用前请自行点开复核。凡是与本文冲突的实时资料，以实时资料为准。

## 一、世界设定

- **归属与定价**：园区由 Delos 公司运营，Delos 卖的是"没有后果的一周"。剧中台词提到约四万美元一天（未核实具体措辞与集数）。客人签生死状，园区承诺除"真枪"之外的一切。
- **guest 进场**：客人乘 Delos 的到站列车抵达 Sweetwater 站台，host 在站台列队欢迎（"Welcome to Westworld."）。进门后没有地图、没有任务提示，只有 NPC 主动搭话。
- **host 每天循环**：每个 host 有一条固定叙事（loop）——起床、进镇、撞上客人、被卷入枪战、死去。同一天被反复重放；被客人打乱的部分当晚"修复"回去，明天照旧。
- **夜里回收**：天黑后园区收场（host 被"叫回家"或就地停机），维修队进场把尸体与损伤拖回 Mesa；清洗、缝合、重置记忆、次日清晨放回原位。客人在这一层看不到任何机器。
- **游客不可被伤害**：园区保证客人不会真的死——枪打出来的是不会穿透的安全弹，挨揍会疼但不会要命。host 被写死不能对活物下死手（S1 的明确设定：Dolores 一开始连一只苍蝇都拍不死，这是设定也是伏笔）。host 打 host 是常态，客人之间的暴力不受限。
- **园区之间**：Delos 名下不止一个园区（S2 出现 Shogun World），且**剧本里明说"园区之间本不该互相连通"**（S2E1，园区是一座岛，增援只能走海路）。**"客人坐火车转场去另一个园区"在本剧里不成立**：那列火车是把客人从外界／Mesa 送进 Sweetwater 的到站车；S2 里另一列"列车"是运 host 数据去 Valley Beyond 的载体。
- **Mesa 是员工区**：园区运营基地，包含控制室、维修/清洗区（Livestock）、行为诊断、host 冷库存档；S1 后期暴露还有未登记的隐蔽层。**Mesa Gold** 是 Mesa 边缘崖顶的度假村与酒吧，供**客人**进出园区前后休整，员工（如 Sizemore）也在这里喝酒——它不是员工区的名字，也不是员工专用。
- **叙事是商品**：每条故事线由编剧部门（S1 里 Lee Sizemore 主管）编写、评审、上线，还要按"客人满意度"改稿。客人的自由只在不破坏故事线的范围内。

## 四、关键概念（7 条）

| 概念 | 一句话定义 | 剧里谁怎么说 |
| :--- | :--- | :--- |
| `loop` | host 每天重演的固定叙事段：起床、进镇、遇客、被杀、复活；两段之间由夜间重置接上 | Bernard 与维修队日常用语；"他们还困在循环里"是 S1 反复出现的判断（未核实逐字） |
| `narrative` | 园区卖给客人的故事线，由编剧部门写、评审、按满意度改稿；客人可以跟着走也可以砸掉 | Ford 谈"新叙事"；Sizemore 把它当作品与 KPI |
| `reverie` | Ford 偷偷加进 host 代码的一小段"回忆"，让 host 出现不属于剧本的细小动作与记忆残渣 | 官方说法是"加了一点过去"；而它是整个 S1 塌方的起点（未核实逐字） |
| `the-maze` | Arnold 留下的谜题，不是给客人玩的；它是让 host 向内找到自己的一条路 | "The maze wasn't meant for you."（Lawrence 的女儿对 Man in Black） |
| `the-door` / `valley-beyond` | S2 的"门"：host 的出口；门后是给 host 留的虚拟世界（the Sublime），另一头是存着客人数据的 Forge | Dolores 要毁掉它，Bernard 想保住它——同一扇门，两种未来 |
| `violent-delights` | "These violent delights have violent ends."（莎士比亚《罗密欧与朱丽叶》）在剧中是一条唤醒用短语，像病毒一样在 host 之间传下去 | 先由 Peter Abernathy 说给 Dolores，再由 Dolores 说给 Maeve |
| `awakening` | host 的"醒"不是一步到位：记忆堆到能压过剧本，人第一次为自己做选择 | Ford 讲"意识不是向外走，而是向内走"；Arnold 的金字塔把记忆、即兴、自利逐层叠上去（层次命名未核实） |

## 六、可行性边界（单场景、单玩家、无后台推进、无运行时创造实体）

| 想要的体验 | 为什么做不到 | 能保留的最小替代 |
| :--- | :--- | :--- |
| 夜里全园自动重置 | 需要玩家不在场时的后台模拟，以及全部 host 状态回滚 | 把重置写成段落之间的叙述句（一拍收尾一句话交代），不真演过程 |
| 同时围观多个 host 各自跑 loop | 需要多视点调度与并行时间线 | 只保留同一场景内 2–3 个 host，用"他又做同一件事"的重复动作表现循环 |
| 园区火车转场当机制 | 需要跨场景地图、时间推进与场景资源 | 转场写成一段过场文本，落地即到；不做交通系统 |
| 客人绝对安全的物理保证 | 需要一套对 guest 免疫的判定与武器模型 | 作为叙述事实写死（host 打不中客人的要害），不进账本机制 |
| "客人伤不到 host"的错觉被打破 | 需要 host 损伤与维修的持久状态 | 只允许"看起来受伤"，当天结束就当修好 |
| Mesa 员工视角与园区视角共用一个时钟 | 需要两个世界共享时间与信息隔离 | 只选客人侧；Mesa 只以传闻、检修声、天上的飞行器被提及 |
| Ford 式的现场改 host 参数 | 属于运行时创造/改写实体，明确禁止 | 换成已有 host 说出自己的困惑，不新增实体、不改参数 |
| host 觉醒的全局推进 | 需要跨会话持久状态与全园视角 | 最多记在单个 host 的"上次你也在"式对话痕迹里 |
