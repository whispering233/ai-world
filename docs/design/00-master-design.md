# 00 总体设计

## 1. 一句话定义

单机单人、中文、浏览器阅读式的文字模拟世界：**世界有一本可被验证的账本，人物只有一次判断，二者之间由唯一的裁判连接。**

## 2. 体验目标

- **人物像人**：会拒绝、会撒谎、会记错、会沉默、会慢慢变。
- **世界可验证**：发生过的事有记录；努力会失败，失败会留痕。
- **无限展开而不崩**：新的地点、人物、事件来自数据，内核不变。

## 3. 非目标（v1）

多人联机 · 实时墙钟 · 图像/语音 · mod 生态 · 玩家下线后的世界推进 · 向量检索 · 代码插件系统。

## 4. 分层

```text
文本层  passage            自由散文，渲染器写，永不进账本
事实层  facts (+ knows)    只增不改，唯一写者为 referee
账本层  ledger             5 类字段 / 7 个 op，唯一写者为 referee
人物层  core(只读) / drives / beliefs / experience(含 self)
调度层  clock(分钟) / busyUntil(最小堆) / journal(append-only)
```

服务边界（**按接口寻址，不直接 import 实现**）：`clock` / `ledger` / `referee` / `narrate`。
每个服务都必须能替换为确定性桩（fixture / 规则桩），否则系统无法测试与回放。

## 7. 设计取舍（为什么这样、不那样）

- **不做能力清单**（tools/skills/动作词表/时长表）：它们限制的是意图空间。本设计要求人物侧零词表，约束只施加在"世界能记住什么"上，并由后果反馈施加。
- **不做阶段化认知**（感知→评价→动机→选择…）：每个阶段是一次有损压缩，多个半判断叠加会稀释判断质量，并让成本按阶段倍增。
- **不做第二写入口**：只要还有另一处能改账本，"世界有真相"就破产。
- **不做多 agent 自由写世界**：人物可以对话，但只有 referee 把主张提交为账本；per-character agent 与 Super-agent 式中央代理最多作为 claim 来源/导演层，不直接写世界状态。
- **不做等距 tick**：世界按分钟变老，不按交互次数变老。
