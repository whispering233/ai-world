# 开发遗留项

## 1. 延后项与触发条件

| 项 | 状态 | 触发条件（何时该做） | 代价 |
| :--- | :--- | :--- | :--- |
| storylet / 导演层（含 Super-agent 式 Router） | 只留位置（claim 第三来源，不写账本） | 玩到第 3 天开始重复、没有推进感、玩家找不到事做 | ~2 周 |
| 离线推进 | 不实现（`advanceTo` 已存在） | 玩家要求"回来时世界变了" | 一天 |
| lorebook 触发注入 | 首切片用 3 条手写 canon 顶替 | canon 超过 ~20 条、上下文放不下 | 2 天 |
| 无歧义 op 直写窄通道 | 不做 | 连买一杯酒也要过裁判，成本明显 | 半天 |
| tag（模糊记忆） | 已否决 | storylet 真需要"按模糊关系触发"时 | 3 天 + 长期腐烂成本 |
| 代码插件（cordis） | 不引入 | **出现第三方代码插件需求**（mod 能加规则/生成器） | 一次移植 |
| 多场景并发 / 多人 | 不做 | — | 高 |
| core 的编辑期更新流程 | 手工 | 内容规模超过十个人物 | 待估 |
| 运行时生成新内容 | 不做 | 手写内容供给跟不上 | 高 |
| 服务端 `/beat` 流式 + `/state` | 未开始 | 世界层三项缺陷（物质不流动 / 知识通胀 / 时间钉死）修完，且 20 拍三条判据至少两条通过 | 2 天 |
| 阅读面（Vite + React + Tailwind） | 未开始 | 服务端落地之后 | 2–3 天 |
| 作者/调试模式（三栏） | 只记录布局决策，不实现 | 需要逐拍查看 claim / verdict / 裁判日志，或编辑内容时 | 2–3 天 |
| per-character agent / Super-agent 世界循环 | 不引入 | 人物需要多步工具调用，且能证明裁判单调用是瓶颈；必须先解决唯一写入口与回放 | 高 |
| 一拍内 cross-talk（可选对话增强 pass） | pilot 不支持默认开启 | 需要更强多人接话感，且 20 拍 + 人工评分证明质量提升 > 2× 认知成本 | 中 |

## 2. 监控指标与阈值

| 指标 | 阈值 | 越界时的动作 |
| :--- | :--- | :--- |
| `no_rate`（分桶） | 15%–40% | 低于 5% 查提示放水；高于 60% 查过严 |
| 长动作占比（`ok`+≥240min） | < 20% | 先查裁判是否把 duration 与当前 clock 混为一谈；换 480 阈值不解决语义问题 |
| `know_rate`（`know` / 全部写操作） | 观察项；>70% 视为知识通胀 | 先查 `REFEREE_SYSTEM` rule 10 的“说话留痕”语义 |
| 名字泄漏（正文出现实体 id） | 0 | 回退 `ContentPack.names/items` 映射 |
| `duration` 分桶 | 观察项 | 0–3 占 90%+ 说明时间钉死 |
| `self` 条目频率 | 每 10 拍 ≤ 1 条 | 超了就收紧 heat 阈值 |
| `phys` 键数量 | 手工维护 | 出现无法一句物理描述解释的键，立即删 |

## 3. 已知失败模式（读代码/跑回合时重点看）

| 模式 | 症状 | 根因 |
| :--- | :--- | :--- |
| 人格湍流 | 人物每拍都在"顿悟" | `self` 闸失效 |
| 鸡汤化 | `self` 条目写成感悟 | 提示缺反例 |
| 空转 | 大量拍无对外变化 | 缺"每拍至少一条可观测变化"检查 |
| 叙事漂移 | 文本写了账本没记的事，之后被推翻 | 渲染器越界写回 |
| 平均人格 | 所有人物听起来是同一个人 | `core` 太短或太礼貌；voice 未生效 |
| 裁判放水 | 玩家做什么都成功 | 缺"拒绝是常态"的提示与指标 |
| 孤独无变化 | 独处一整天毫无变化 | 长动作签名阈值未生效 |
| **物质流薄** | 有 `transfer`/`consume`，但净持有变化很小，远少于 `know/fact` | 裁判倾向把一切写成"说"；来回 transfer 会虚增流动感 |
| **知识通胀** | `know` 占全部写操作七成以上 | 每次对话都同步一遍事实，等于把"谁知道"当"发生了什么" |
| **时间钉死** | 20 拍只走几十分钟，`duration` 恒为 1–3 分钟 | 裁判没有长动作的动机；提示未给时长参照 |
