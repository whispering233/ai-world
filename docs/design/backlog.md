## 2. 监控指标与阈值

| 指标 | 阈值 | 越界时的动作 |
| :--- | :--- | :--- |
| `no_rate`（分桶） | 15%–40% | 低于 5% 查提示放水；高于 60% 查过严 |
| 长动作占比（`ok`+≥240min） | < 20% | 先查裁判是否把 duration 与当前 clock 混为一谈；换 480 阈值不解决语义问题 |
| `know_rate`（`know` / 全部写操作） | 观察项；>70% 视为知识通胀；2026-11-26 三次为 9.5% / 0% / 0% | 先查 `REFEREE_SYSTEM` rule 10 的“说话留痕”语义 |
| `facts/beat`（事实数 / 拍数） | 长期 ≤ 1.0；2026-11-26 三次为 0.55 / 1.25 / 0.80，C7 后 0.85 | 继续观察；不许改 `FACT_BUDGET` 掩盖 |
| 名字泄漏（正文出现实体 id） | 0 | 回退 `ContentPack.names/items` 映射 |
| `duration` 分桶 | 观察项 | 0–3 占 90%+ 只说明默认探针全是短动作；跑 `--long` 看长动作能否 ≥240 |
| `self` 条目频率 | 每 10 拍 ≤ 1 条 | 超了就收紧 heat 阈值 |
| `phys` 键数量 / 未登记键 | 观察项；新增键同步登记 `db/schema.md` §9 | 出现无法一句物理描述解释的键，立即删；连续多局只有单向值的键，标出“解除者缺失” |

## 3. 已知失败模式（读代码/跑回合时重点看）

| 模式 | 症状 | 根因 |
| :--- | :--- | :--- |
| 人格湍流 | 人物每拍都在"顿悟" | `self` 闸失效 |
| 鸡汤化 | `self` 条目写成感悟 | 提示缺反例 |
| 空转 | 大量拍无对外变化 | 三次 77% / 60.6% / 71%，C7 后 69%；主要是纯对话/姿态，外套/抹布已入账，台面内坐标仍未建模；不要逼每拍落 op |
| 叙事漂移 | 文本写了账本没记的事，之后被推翻 | 渲染器越界写回 |
| 平均人格 | 所有人物听起来是同一个人 | `core` 太短或太礼貌；voice 未生效 |
| 裁判放水 | 玩家做什么都成功 | 缺"拒绝是常态"的提示与指标 |
| 孤独无变化 | 独处一整天毫无变化 | 长动作签名阈值未生效 |
| **phys 键漂移** | 同一状态多种键（`closed` / `bolted`），或键里塞了位置（`blocking_counter`） | 开放口袋 + 无登记；`apply` 不校验键名 |
| **phys 键粘住** | 只写过 `true`、从没写回 `false`（`door.bolted`） | 键没有解除动作，账本也没有状态过期机制 |
| **事实残留脏数据** | `facts/beat` 高于 1.0：动作细节、重复寒暄、主语归属错 | 已加可选 `actor`/`kind`，但字段覆盖不等于语义正确；baseline-21 为 1.25，重复/语义问题仍需人工抽样 |
| **物质流薄** | 有 `transfer`/`consume`，但净持有变化很小，远少于 `know/fact` | M1 后 12 拍 material 7、5/5 `transfer` 涉及陈设；baseline-20 第 6 拍已成交一杯威士忌；C7 后 12 拍 coat 2 次、rag 1 次、失败 op 0；铁盒解锁是角色 gate |
| **知识通胀** | `know` 占全部写操作七成以上 | 2026-11-26 后三次 20 拍均为 0 条 `know`（baseline-20 旧内容有 2/21），**未复现**；继续观察，不先切卡 |
| **时间测量假象** | 默认 smoke 全短句，`duration` 0–3；容易被误读成“时间钉死” | 跑 `--long` 长动作探针；等雨 4 小时已给 240，睡整夜给过 480；不要加强制下限 |

## 6. UI 待办（组件库迁移之后）

### 6.0 已否决：用 `CodeHighlighter` 替 `<pre>`

量过了：只换 `LedgerView` 的 JSON 与 `BeatDetail` 的两处 prompt，构建产物从 **1.12 MB / gzip 354 kB** 涨到 **1.79 MB / gzip 592 kB**（+667 kB raw、+238 kB gzip）。换来的只是一个复制按钮与 JSON 上色，而当时它是**玩家壳也要下载的同一个 chunk**。

**前提已变**：作者壳现在是懒加载的（`AuthorApp` 单独 94.8 kB / gzip 31 kB），这 +238 kB 会落进作者 chunk，只在打开作者视图时下载。要做得重新量一次那个 chunk 的收益，别拿旧数字否掉。

两条都不是样式活：各自卡在一条没定的语义契约上，契约定了才能切卡。

### 6.1 对话与场景描写分开渲染

**现状**：`passage.text` 是**单个字符串**，`NARRATOR_SYSTEM` 明确要求「只输出散文本身」（`packages/core/src/narrate.ts`）；渲染端一段 `<p>` 到底，对话与旁白无法区分。作者侧 `PassageView.source` 只有 `narrator`/`player`/`npc`/`fallback` 四档，表达不了「某一句是谁说的」。

**卡点**：说话人从哪来。三条路（业界都没用 JSON）：

1. **引号约定**：`"…"` = 台词、其余 = 旁白。零结构成本，但引号嵌套与长旁白会漂（SillyTavern / RisuAI 走这条）。
2. **行首 `名字：台词`**：解析最简单、对中文最自然（Ren'Py 的 `narrator` 与 WebGAL 的 `speaker:` 都是这个范式），解析失败整段退化为散文。
3. **模型输出带标记**：要动 `narrate` 的产出契约与 `passage` 落盘格式，回放与旧档兼容都要一起改。

**已经确定的事实**：`Bubble placement="end"` 在普通块级父容器里**不会右对齐**（实测，两条气泡 `left` 都是 24px），要用 x 的气泡得自己补布局或改走 `Bubble.List`。
**当前进展**：决策 #44 只做了旁白上限（最多 1–2 段人物段落、按 `referee.order`），**说话人字段仍未定**；Q4 不解决“某一句是谁说的”。

### 6.2 等待与思考过程反馈

**现状**：第一档已落地——服务端每 1s 发 `{elapsedMs, clockText}`（`progress` 帧兼作心跳），UI 是「世界在回应… 00:12 ▍」+ 玩家那句话下面的三条骨架。第二档已落地：裁判返回后发 `phase:'settled'`，文案“这一拍已经定了，正在落笔…”。输入区状态行与“等一会儿”按钮也已落地（决策 #46/#49）。

**不复评的档**：阶段步骤条（“人物在想 → 世界在裁定”）不可观测，会变成假进度；token 流不解决 22s 的裁判段，且要改旁白接口、SSE、绝对时间校验与兜底。两者都不做，触发条件见 §1。
