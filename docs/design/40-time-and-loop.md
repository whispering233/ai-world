# 40 时间、场景与主循环

## 1. 时间模型

| 概念 | 定义 |
| :--- | :--- |
| `clock` | 从创世起的**分钟数**，单调递增 |
| `busyUntil` | 每个实体"手上这件事完成"的时刻 |
| `beat` | **一拍**：一次结算 = 一条 `journal` = 一个回放单位 |
| `scene` | **一个场景**：一次装配 → 若干拍追加 → 一次折场（见 §2） |
| `fmt(clock)` | 唯一的时间展示出口，如 `第 3 天 · 傍晚` |

**没有等距 tick。** 世界按分钟变老，不按交互次数变老。
**一拍不是时间边界**，是事务边界；一拍的时长由 referee 给，可能 1 分钟，也可能 8 小时。

时钟只按**已提交 claim** 的最大 `duration` 推进：被拒绝（`ok:false`）或整条回滚的 claim 不推进 `clock`。否则一条没有落账的“睡一整夜”也会把世界推进 8 小时，和“一拍事务全成或全退”冲突。

## 2. 场景（一等概念）

场景是**上下文的生命周期单位**，不只是"同一地点的连续时刻"。

| 时点 | 动作 |
| :--- | :--- |
| 进入 | **装配**：检索记忆（用满 25% 预算）、取 canon、算账本切片，拼出每个参与者自己的上下文 |
| 场景内 | **只追加**：每拍在尾部追加新文本，不改动前缀（缓存命中）。每人追加的是**自己那句 + 裁判给本人的感知摘要**，不是全员台词广播 |
| 退出 | **折场**：把该场景窗口压成 1–2 条 `experience`（可能是 `self` 条目），写一条 `journal.scene/fold` |

**折场条件（任一即折）**：

| 条件 | 说明 |
| :--- | :--- |
| 地点变化 | 主视角实体的 `at` 发生变化 |
| 时间跳跃 ≥ 240 分钟 | 与“长动作签名”共用同一阈值 |
| 已满 12 拍 | 节奇上限 |
| 已达 16k tokens | 上下文上限 |

折场是唯一的压缩入口，同时是成长入口。

**折场在同一次结算内完成**：写 `journal.scene/fold` 之后立刻装配下一个场景（拍数与上下文归零），`runBeat` 返回的场景就是下一拍要用的场景。重开是结算的一部分，调用方不需要（也不该）自己再开一次——两份循环各自持有这条责任时，必然有一份会漏。

**`tokens` 的口径**：本场景**当前最长参与者上下文**的估算值（每人一份 `context`，取最长的那个），折场后归零。它不是本拍增量（会让上限永远差一个数量级），也不是所有人之和（会把 4 人场景提前 4 倍折掉）。

场景不单独落盘：场景边界由 `journal.scene` 与 `scene/fold` 记录推出；场景 id 取折场那条 journal 的 `seq`。

## 3. 主循环

```text
loop:
  if 无当前场景: 装配场景（检索 + canon + 账本切片）
  actors  = 被叫到的人(场景)
  claims  = 收集(actors + 玩家)
  if claims 为空: clock = min(busyUntil); continue
  r       = referee(claims, 场景切片, 账本, canon)   // 一拍一次
  clockAfter = clock + max(已提交 claim 的 duration)
  账本原子提交(r); 追加渲染(r); 写日志(clockAfter, scene, claims, r)
  clock   = clockAfter
  if 拍数 ≥ 12 或 tokens ≥ 16k 或 地点变化 或 时间跳跃 ≥ 240 或 场景为空: 折场()
```

## 4. 被叫到的人

一拍参与者 = 玩家（总是） ∪ { 有张力者（`max(heat) ≥ 0.5`） ∪ 本拍被直接作用者（被点名、被告知、被攻击） }

**聚焦模式例外**：玩家选了“对谁说”时，本拍只叫玩家 + 目标，其余人不产生 claim（决策 #48）；默认“所有人”走上式。

**在场 ≠ 醒着。** 同 `placeId` 只是位置属性，不作为唤醒条件。
沉默者的自救机制：`drive` 受阻会 `heat +0.2`，越沉默越烫，迟早被叫到。

## 5. 时长归属

`duration` 属于**世界事实**，不属于角色意图，因此由 referee 给出。

| 规则 | 值 |
| :--- | :--- |
| 缺省 | 1 分钟 |
| 上下限 | `[0, 1440]` |
| 超过一天 | 必须显式是长动作（睡、远行、养伤） |
| 空间类动作 | 可由距离/速度算术推导，不查动作时长表 |

角色与玩家可以在文本里表达时长（"我等到傍晚"），referee 采纳或修正；最终值以 referee 为准。

`duration` 是**动作本身**的耗时，不是“当前 clock 是否已经走到那个时刻”。裁判不能因为“从进门到现在才过了六分钟”拒绝“睡一整夜”；它只需要判断这个动作是否成立，再给出耗时。

**不做动作时长表**：那是能力清单的第三种形态，会长不完。

**短对话不等于时间钉死**：默认 experiment 只喂 12 拍短句，走 17 分钟是正确的；`play` 的 20 拍里睡一整夜给过 480 分钟，`experiment --long` 的“等雨四个钟头”给过 240 分钟（clock 9→249，拂晓）。不要为了“让时间走”给 `duration` 加强制下限；长动作被拒先看场景是否成立。证据见 [time-probe-smoke.md](../research/time-probe-smoke.md)。

`clock` 只按**已提交** claim 的最大 duration 推进；判断“本拍是否时间跳跃”要用**上一拍结束时刻**，不能用 `scene.lastBeatAt`——它已被本拍推到结束了。

## 6. 时间只有一个出口

叙事文本**禁止写绝对时间**，只能用 `fmt(clock_before)` 与 `fmt(clock_now)` 推出的相对说法（"天已经黑了"）。

于是"文本说傍晚、clock 说上午"这类矛盾在结构上不可能发生。这比任何校验都值钱。

## 7. 世界签名（成长许可）

| 条件 | 是否算签名 |
| :--- | :--- |
| `verdict: ok` 且账本有变化 | 是 |
| `verdict: no` | 是（挫败也是经历） |
| `verdict: ok` + `deltas: []` + `duration ≥ 240` | 是（时间流逝本身有分量） |
| `verdict: no` / 整条回滚 | 不计入 clock；是否算经历由折场另判 |
| 其余 | 否 |

折场时若本场满足上述任一条件，则允许写 `self` 条目（仍受"稀缺"与"具体"约束，见 30 §4）。

## 8. 推进与暂停

- v1：**玩家在场时，时间只由主张推进**；不按真实墙钟流逝，慢读者不被惩罚。
- “等一会儿”是玩家提交的一条普通等待 claim，不是后台推进：裁判照常给时长，世界照常结算（决策 #49）。
- 玩家离线：世界不推进（v1）。
- `advanceTo(t)` 已存在于主循环形态中，离线粗粒度推进是**纯增量**，不改变架构（见 backlog）。

## 9. 明确不做

- 等距 tick / 回合计数
- 真实墙钟推进
- 多时间尺度嵌套
- 预排的导演事件队列
- 后台心智活动
- 场景表落盘（场景是派生概念）

## 10. 一拍内部的并发与降级

### 10.1 认知并发

同一拍里多个人物的判断互不依赖（谁也不知道谁这一拍会说什么），因此**并发发起**，按人位顺序收集结果。这不改变任何语义：结算顺序仍由裁判给出的 `order` 决定，claim 的先后只影响叙述排版。

串行版每拍多花一次认知的时间（约 10 秒）；五人在场时差异最明显。

### 10.2 人物失败 = 本拍沉默

单个人物调用失败，视同**它这一拍没开口**：不产生 claim，其余人照常结算，本拍照常落账。失败原因写进 `notes`，不许静默吞掉。

理由：人物的沉默本来就是合法结果（`outward` 可以为空），把一次网络超时解释成"没说话"比让整拍作废更接近世界语义。

### 10.3 裁判失败 = 本拍无进展

裁判是唯一写入口，它失败意味着**没有任何事被确认发生**。此时整拍空转：账本不动、时间不推进、不落 journal、不产出叙述，只留一条 `notes`。

这条比 10.2 严格得多，因为一旦允许"没结算就往下走"，账本就再也无法作为证据。
