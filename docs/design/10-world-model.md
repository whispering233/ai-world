# 10 世界模型

## 1. 三份数据

| | 内容 | 写者 | 可变性 |
| :--- | :--- | :--- | :--- |
| `passage` | 叙事、对话、内心独白的**呈现文本** | 渲染器 | 只增，永不修改 |
| `facts` | **发生过的事**（事件流，含言语事件） | referee | 只增；推翻旧条目 = 新增 + `supersededBy` |
| `ledger` | 可被外界观测/验证的状态 | referee | 每拍可变 |

世界根还带一张 `places` 白名单（id → 人读的名字）：地点不是自由字符串，`move` 只能去已登记的地方，否则模型会现编地名把玩家传送到不存在的地点。

人物/物品的显示名不放进世界根：它们是作者层 `ContentPack.names/items`，只影响 prompt 与正文，不参与 replay，也不进账本。

**文本不是证据。** 账本与文本冲突时以账本为准，且**不 retcon**：已经发出的文本永不改写，只让后续生成向账本收敛。

## 2. 账本字段（5 类）

| 字段 | 含义 | 形态 |
| :--- | :--- | :--- |
| `at` | 位置 | `EntId → PlaceId` |
| `holds` | 持有物 | `EntId → {ItemId: count}` |
| `phys` | 物理属性（门锁、伤势、灯火、火势…） | `EntId → {string: number\|boolean}`，**键开放** |
| `rel` | 关系强度 | `EntId → {EntId: -3..3}` |
| `knows` | 是否知情 | `EntId → FactId[]` |

`phys` 是开放口袋，唯一约束：**键必须能被一句物理描述解释**，且 v1 手工维护键表。

**`knows` 的差集就是全部悬疑与秘密**，因此不另建秘密系统。

## 3. 写操作（7 个：5 个改标量 / 1 个改数组 / 1 个增事实）

| op | 作用 | 前置条件（在 op 内部检查） |
| :--- | :--- | :--- |
| `move` | 改 `at` | 实体存在；**目标地点必须在 `places` 白名单里** |
| `transfer` | 改 `holds`：从 `from` 转到 `to` | 双方存在；给出方确实持有足够数量 |
| `consume` | 从 `holds` 移除，物品离开世界 | 持有方确实持有足够数量 |
| `phys` | 改 `phys[key]` | 目标实体存在 |
| `rel` | 改 `rel` | 双方存在；结果**饱和**到 `-3..3`（不拒绝） |
| `fact` | **新增**一条事实（发生过的事），不授予任何人 | 文本非空 |
| `know` | 向若干实体授予知情。`fact` 可以是事实 id，也可以是**一句话的事实**（不存在则当场新建） | 对象存在；事实未被 superseded |

`transfer` 表示**任何持有变化**：自愿给、抢夺、没收都用它；`consume` 只表示物品离开世界（喝掉、烧掉、用掉），没有接收者。旧 journal 里的 `give` / `take` 只作为 replay 别名保留，新的裁判输出只用 `transfer` / `consume`。

`fact` 与 `know` 必须分开：**事实可以存在而无人知晓**（世界真相、秘密），而知情可以事后追认（“Doc 后来听说了那件事”）。合并成一个 `learn` 会退化成“新增一条关于知情的元事实”，把真相污染成传闻。

**没有独立的审核阶段。** 校验就是每个 op 自己的前置条件；不合法时该 op 返回失败并记入日志。

## 4. 五条不变式

1. 文本不是证据。
2. 不 retcon。
3. 只有 referee 能写 `ledger` 与 `facts`。
4. `fact` 只增不改。
5. 每拍至少一条可观测变化（账本 delta / 对外文本），否则判为空转并压低其优先级。

## 5. `knows` 与 `belief` 的分工

| | 含义 | 存放 | 可错性 |
| :--- | :--- | :--- | :--- |
| `knows` | 此人**是否**知道某条公共事实 | 账本 | 不可错（由 referee 授予） |
| `belief` | 此人**以为**什么 | 角色私有 | 可错，可被谎言改写 |

人物说错话是合法的：谎言进入世界的方式是"新增一条 fact（他说过这话）+ 授予听众 knows"，原事实不受影响。

`know` 不是"每句话广播"：在场者的即时记忆由 `observations` / `experience` 记录；只有听众原本不知道、且以后会用到的信息（秘密、计划、债务、身份、跨场景承诺）才写 `know`，一次用 `who` 数组覆盖所有听众。`knows` 在 v1 还没有消费者；先把语义收窄，接入认知/裁判是后续卡。

## 6. 记忆的不对称（设计原则，不是妥协）

> **世界记得少而硬，人记得多而软。**

- 账本：7 个 op，只记别人能验证的；`facts` 记发生过的事，真假由账本决定。
- 角色 `experience`：不受 op 限制，记一切它经历与在意的事，只受上下文预算约束。

因此：一次深夜长谈不会改变任何账本，但当事人记得，并会在下一轮改变它说话的方式。这是"细腻的行为也能留下后果"的唯一通道。

代价（明确接受）：粗暴的、可见的、有物的行为，比细腻的内在行为更容易被世界记住。

## 7. 事件流怎么喂给裁判

事实是事件流，不是世界真理。喂给裁判时必须**择优**，否则早期后果会被后来的噪声挤掉：

- **推翻的不喂**：带 `supersededBy` 的事实已失效，喂了等于让裁判拿旧结论推理。
- **权重**：提到在场者 +2，十分钟内发生 +1。
- **名额 12**：按权重降序取，超出名额的按时间倒序补齐。
- **展示顺序**：选完再按时间正序排列，读起来像一条时间线，而不是排行榜。

名额是权衡不是常量：太小会让因果断链，太大则挤掉现场描述、稀释裁判注意力。改变名额必须同时跑 20 拍回归对比 no_rate 与"后果回响"的出现率。
