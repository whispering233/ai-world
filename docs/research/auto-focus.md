# 没点目标时的名字自动聚焦（C10）

- 2026-11-26

## 行为

- 玩家没给 `to`（或给空白）时，服务端在 `text` 里找**本场非玩家人物**的显示名/别名。
- 命中实体恰好 1 个 → 该拍 `playerTo` 设为其显示名；0 个/多人 → 所有人。
- 显式 `to` 永远优先；显式 `to` 对不上人时只记 `notes`，**不**回退自动推断。
- 不解析动作、不分词、不猜代词；不读 `here` 以外的人。
- 自动成功不写 note；失败就是原来的所有人调度。

## 验证

- 测试 **391**（33 文件），typecheck/build 绿。
- 纯函数 9 例：唯一名字、两名、别名、显示名+别名同一人、无人名、只有玩家名、同名两人、空标签、不在场的人。
- 路由 5 例：
  - `{"text":"我走到安面前，把银元放下。"}` → `playerTo === "安"`；
  - 文本提到安和科迪 → 无 `playerTo`；
  - 显式 `to:"科迪"` 而文本只提安 → `playerTo === "科迪"`；
  - 显式 `to:"不存在"` 而文本提安 → 无 `playerTo`（不回退）；
  - `to:"   "` + 文本提安 → 仍然自动聚焦。
- 没有跑真实 20 拍/浏览器；本卡只验证解析层与路由契约。

## 已知限制

- 单字显示名（安/门/灯）会误命中同字词：“稍微安心”会聚焦安。本轮接受，已用测试钉住；要收紧需分词或作者提供长别名。
- UI 的“所有人” chip 与“未选目标”都是不发 `to`，服务端无法区分；想显式广播只能等后续的独立字段/UI 状态。当前 passage 落定后可能显示“你（对安）”，chip 仍是“所有人”。
- `ContentPack.aliases` 原本只用于事实切片匹配；现在也参与自动聚焦，作者写短别名会更易误命中。
