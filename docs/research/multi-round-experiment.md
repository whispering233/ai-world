# 一拍内多轮对话实验（pilot）

> 目的：验证“多 agent 更灵活”是否成立。具体问法：**让人物在一拍内看到彼此的公开输出后再定稿，是否比“各自想一次”或“各自想两次但看不到别人”更好？**
>
> 结论先行：**cross-talk 确实让对话更互相接得住，但没有让世界状态更一致；成本约 +10%（对 self-retry）/ +20%（对 baseline），且拒绝率翻倍。** 证据不足以支持 per-character agent 或去掉裁判；只支持把 cross-talk 当作一个可选的“对话增强 pass”。

## 1. 实验设计

三臂，同一模型、同一内容包、同一玩家输入序列：

| 臂 | 认知调用 | 第二轮看到什么 | 用途 |
| :--- | :--- | :--- | :--- |
| `baseline` | 每人 1 次 | — | 当前生产行为 |
| `self-retry` | 每人 2 次 | 只看到自己的草稿 | 控制“多一次调用”本身的效果 |
| `cross-talk` | 每人 2 次 | 看到其他人的公开 `outward` | 实验组 |

- 只共享 `outward`；`inner` 永不跨人。
- 第二轮后，每人仍只提交**一条** claim；裁判仍是唯一写入口。
- 玩法输入固定为 10 条循环（见脚本 `AUTO_LINES`），每臂独立跑，轨迹会因 LLM 非确定而分叉。
- 运行：`npm run experiment:multi-round -- --beats 6 --mode all --tag pilot-3`
- 脚本：[`scripts/experiment-multi-round.ts`](../../scripts/experiment-multi-round.ts)
- 产物：`data/experiment/pilot-3/<arm>/{journal.jsonl,passage.jsonl,metrics.jsonl,metrics.json,report.md}`

## 2. 结果（pilot-3，6 拍）

| 指标 | baseline | self-retry | cross-talk |
| :--- | ---: | ---: | ---: |
| 拍数 | 6 | 6 | 6 |
| 时钟推进 | 11 min | 12 min | 12 min |
| 墙钟总耗时 | 331.8s | 360.3s | 398.9s |
| 每拍均耗时 | 55.3s | 60.0s | 66.5s |
| 认知调用 | 24 | 48 | 48 |
| 输入 tokens | 42,214 | 55,696 | 58,276 |
| 输出 tokens | 25,450 | 30,928 | 34,178 |
| 裁决数 | 30 | 30 | 30 |
| `no_rate` | 6.7% | 6.7% | **13.3%** |
| 空结果占比 | 6.7% | 20.0% | 6.7% |
| 硬冲突 | 0 | 0 | 0 |
| 双花候选 | 0 | 0 | 0 |
| op 失败条数 | 0 | 0 | 0 |
| 交叉对话改口 | — | 23/24 | 24/24 |
| 交叉对话回声（4-gram） | — | **0/24** | **11/24（45.8%）** |

写操作分布：

| 臂 | move | give | take | phys | rel | fact | know |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline | 0 | 1 | 0 | 1 | 2 | 24 | 54 |
| self-retry | 0 | 3 | 1 | 0 | 1 | 22 | 59 |
| cross-talk | 0 | 2 | 1 | 1 | 4 | 24 | 68 |

> 本表记录 pilot 时的旧 op 名（give/take）；现对应 `transfer`/`consume`。

### 复现（pilot-2，6 拍，加 echo 之前）

| 指标 | baseline | self-retry | cross-talk |
| :--- | ---: | ---: | ---: |
| `no_rate` | 6.7% | 6.7% | **13.3%** |
| 硬冲突 | **1**（双花 1） | 0 | 0 |
| op 失败 | 1 | 0 | 0 |
| 墙钟总耗时 | 308.9s | 410.4s | 436.7s |

两次 pilot 的一致信号：**cross-talk 的 `no_rate` 都是 13.3%，baseline/self-retry 都是 6.7%；cross-talk 没有产生硬冲突，baseline 在一次 pilot 里出现 1 次双花。**

## 3. 怎么读这些数

### 3.1 cross-talk 确实在“接话”

`self-retry` 的回声率是 **0/24**（它看不到别人，4-gram 重叠为 0）。`cross-talk` 是 **11/24（45.8%）**：
- 安会直接点名道森：“道森，你先说。”
- 科迪会同时接安和道森的话，并替玩家把“整瓶还是单杯”的账摆到台面上。
- 格蕾妮会针对账本做出动作，而不是只擦桌子。

这证明第二轮不是“多写一点”，而是**真的把别人的话吃进了自己的输出**。

### 3.2 但世界没有因此更一致

- 三臂硬冲突都是 0；cross-talk 没有比 self-retry 更少冲突。
- 双花/矛盾不是靠“人物多聊两句”解决的，而是靠裁判的批量裁决和事务提交。cross-talk 只是让 claim 更丰富，**没有改变提交层的职责**。
- 这也说明：多 agent 的“灵活”体现在**对话生成**，不体现在**状态一致性**。

### 3.3 拒绝率翻倍：可能是好事，也可能是坏事

cross-talk 的 `no_rate` 从 6.7% 升到 13.3%，两次 pilot 一致。

两种解释：
- **好事**：人物看到别人已经占了位/放了话，更敢拒绝、更敢争，裁判不再放水。
- **坏事**：第二轮让 claim 更“满”，互相冲突更多，裁判更频繁地说 no；世界推进变慢。

6 拍样本无法区分。需要 20 拍 + 人工读“拒绝是否合理”，而不是只看比例。

### 3.4 成本

- 对 `baseline`：认知调用 2×，墙钟约 +20%，输出 tokens 约 +34%。
- 对 `self-retry`：认知调用相同，墙钟约 +10.7%，输出 tokens 约 +10.5%，输入 tokens 约 +4.6%。
- 也就是说，**cross-talk 的额外成本主要不是“多一次调用”（self-retry 已经付了），而是“多看到别人的文本”带来的输入增长和更长的输出**。

## 4. 人工样本

### cross-talk 第 3 拍（节选）

> 安的手没离开账本封面，抬眼扫过玩家的袖口，又落到道森那边。她问：铁盒里的东西，怎么到他手上？道森，你先说。
>
> 道森把扣下的牌又捻了捻……他的视线从安压着账本的手挪到格蕾妮腰上的钥匙。
>
> 科迪……说，安，你先把手从那上头挪一挪，本子又不会长腿跑了；道森，你牌都扣了，还盯什么？
>
> 格蕾妮……把账本朝安那侧推平半寸。指头搭上封角，按了按，本子一动没动——安的抹布和手掌还压在上头。

这是三人互相接话、并且把冲突落在同一个物件（账本）上的样本。

### self-retry 第 3 拍（节选）

> 安没去接，一块湿抹布先压到账本封皮上……“这个不摆柜台。”
>
> 多克的手指在桌面上搭了一会儿，慢慢收回来……“锁着的那本，不认人。摊开的这本……认。”
>
> 科迪清了清喉咙……“账本搁在柜上又不会长脚……先倒酒。”
>
> 奶奶始终没出声，手按在钥匙串上……

每个人都在对玩家/账本表态，但彼此之间没有形成“你一句我一句”的对话链；而且名字泄漏（“多克”“奶奶”）比 cross-talk 更明显。

**注意**：当时两臂都还有 id/名字泄漏（`player`、`ann`、`doc`、`cody`、`granny` 进旁白）；后续已用 `ContentPack.names/items` 修复，见 `docs/research/world-baseline.md` 的名字泄漏计数。

## 5. 结论

1. **多 agent 更灵活，但只在生成层。** cross-talk 确实让人物互相接话（回声 45.8% vs 0），但没有减少硬冲突；世界一致性仍由裁判保证。
2. **不建议现在改成 per-character agent 或去掉裁判。** 这会丢掉唯一写入口、事务提交和回放，而实验没有证明它能带来相应的世界质量提升。
3. **cross-talk 可以作为可选“对话增强 pass”**：放在裁判之前，默认关闭；只有在 20 拍 + 人工评分证明“质量提升 > 成本”时才考虑默认开启。
4. **下一步如果要继续**：
   - 跑 20 拍三臂，加入人工 1–5 分评分（接话、人物声音、拒绝合理性、推进感）；
   - 先修玩家可读名称（人物/物品），否则名字泄漏会污染评分；
   - 把 `no_rate` 分桶看（拒绝是否合理），不要只看总比例；
   - 如果 cross-talk 胜出，先做成配置开关，不要改默认。

## 6. 顺带发现并修复的基线 bug

`runBeat` 此前只把玩家输入放进 claims，**没有放进人物认知的 prompt**；也就是说，人物看不到玩家这一拍说了什么，只有裁判看得到。实验前已修复：

- `src/core/beat.ts`：`sceneFor()` 追加 `玩家刚才说/做：...`
- `tests/beat.test.ts`：锁住人物 prompt 含玩家输入

这个 bug 会让 baseline 明显偏弱；修完后两臂才在同一基线上比较。

## 7. 限制

- 6 拍 pilot，不是 20 拍；样本小，不能做统计显著性主张。
- 三臂轨迹因 LLM 非确定而分叉，不是同一轨迹的 A/B。
- `no_rate`、回声率、硬冲突都是启发式指标；拒绝是否合理、人物声音是否更好仍需人工读。
- 只测了一个模型（`opencode-go/deepseek-v4.1-flash`）和一个内容包。
- 实验脚本是 disposable driver，复制了 `runBeat` 的部分私有逻辑；生产路径没有因此改变。
