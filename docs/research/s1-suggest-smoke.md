# S1 动作提示 smoke（s1-suggest）

- 2026-11-26
- 12 拍 baseline；四个角色均为 `opencode-go/deepseek-v4.1-flash`
- 命令：`env -u PI_MODEL node --experimental-strip-types scripts/experiment-multi-round.ts --beats 12 --mode baseline --tag s1-suggest --force`
- 目的：验证 `suggest` 与旁白并行、提示落 passage、真浏览器里点选只填不发，并看耗时/no_rate 是否被拖坏。

## 1. 总量

| 指标 | M1 陈设承载 | S1 动作提示 |
| :--- | ---: | ---: |
| 每拍均耗时 | 62.7s | **61.1s** |
| 时钟推进 | 16 分钟 | 17 分钟 |
| no_rate | 11.7%（7/60） | **6.7%（4/60）** |
| 空结果占比 | 66.7%（40/60） | 71.7%（43/60） |
| 硬冲突 / 双花 / 失败 op | 0 / 0 / 0 | 0 / 0 / 0 |
| 动作提示 | - | **12/12 拍，36 条** |
| `transfer` / `consume` / `phys` | 5 / 0 / 2 | 5 / 0 / 1 |
| `rel` / `fact` / `know` / `move` | 1 / 7 / 0 / 1 | 1 / 8 / 1 / 0 |
| 输入 / 输出 tokens | 143.8k / 86.0k | 127.9k / 80.4k |

提示与旁白并行：拍均耗时没有上升（61.1s vs 62.7s），`suggest` 调用 12/12，全部在 passage 落盘。

## 2. 提示质量

- 12 拍全部 3 条，共 36 条；没有空数组。
- 每条按码点 ≤40；36 条里没有实体/物品/地点 id，也没有引擎词（脚本 + 代码过滤双重检查）。
- 例子：
  - “把两枚银元推到柜台上，指指安手边那只杯子”
  - “问科迪嗓子干成这样，平时在哪儿喝”
  - “朝门边的格蕾妮抬抬下巴，问她手里那串钥匙开哪扇门”
- 它们接的是**玩家可见**的现场、持有、已知事实与刚刚的感知；没有把别人的 claim 或裁判理由喂进去。
- 不足：少数提示会重复玩家刚做的动作，或建议一个未必成立的动作（“低头看账本最后一页”）；提示是候选，不是承诺，失败仍由裁判拒绝。

## 3. 真浏览器

- 新局、0 拍；点“等一会儿”，等待 1 拍完成（约 60s）。
- 最近一拍下方出现 3 条选项，固定在状态行上方；状态行仍是“酒馆 · 你身上：银元×2”。
- 点第一条：输入框变成它的原文；没有发送、没有 loading、`GET /api/session` 仍是 1 拍。
- 深色主题下选项可读；浏览器证据已记为 `s1-suggest-browser`（options / fill / clean / state 全部通过）。
- 测试用临时 `data/starter-town`，结束后已恢复原数据；服务已停。

## 4. 结论

- `suggest` 的并行、持久化、投影、UI 点选链路都成立；失败只丢提示，不影响账本与本拍。
- no_rate 从 11.7% 降到 6.7%，空结果略升到 71.7%；单次 12 拍不足以说明趋势。
- 提示能降低“不知道输入什么”的空白，但不保证建议的动作会被裁判接受。

## 5. 风险

- 只跑了一次 12 拍；提示命中和 no_rate 都有采样波动。
- 提示没有点击率/采纳率指标；“生成 3 条”不等于“玩家愿意用”。
- 模型仍可能给出与账本冲突的动作；当前只做 id/引擎词过滤，不做语义校验。
- `suggest` 调用在 baseline 才有；实验脚本的 self-retry/cross-talk 臂未接提示，报告已注明。
