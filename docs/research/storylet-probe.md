# storylet 探针：裁判认不认「没有人的世界事件」

> 探针时间：2026-11-22。目的：A 方案（作者写骨架 + 只读条件 → 抽卡产出世界事件 claim → 裁判裁决）最可能死在裁判这一步。探针只测这一步，不测条件求值器与填肉。
>
> 结论先行：**非人 actor 不是障碍，“没有因”才是障碍。** 无人竞争时 3 条里放行 1 条、拒 2 条，拒的理由全部是“缺前因”，没有一条说“死物不能当 actor”；一旦玩家在同一拍做出竞争动作，世界事件 3 条全部不落账。
>
> 后续：v1 见 §7 §8（**净收益为负**：+21% 墙钟、一张牌连抽 6 次、7 条只落账 1 条，填肉还会替人物做动作）；v2 见 §10（冷却 + 模板文本，落账 2/2、边际成本 0，但空转拍没降）；v3 见 §12（两级前因：`ambient` 管环境、`facts` 管后果，落账 3/3，**净效果 1 个死拍**）。

## 1. 问题

设计上 storylet 只能作 claim 第三来源（[../design/00-master-design.md](../design/00-master-design.md) 决策 31）。但裁判的提示词是按"人做事"写的，未知点是：

1. 裁判会不会拒绝 `actor` 是 `lamp` / `door` / `cellar` 这类账本实体、但没有人驱动的 claim？
2. 放行时它会不会真的写 `phys`，还是只给一句 `ok + deltas:[]`（那等于没治空转）？
3. 和玩家的动作抢同一个世界状态时，账本认谁？

## 2. 方法

| 项 | 取值 |
| :--- | :--- |
| 调用 | 6 次真实裁判（3 个 storylet × 2 臂），无人物、无旁白调用 |
| 臂 | `world`：只交世界事件；`competition`：世界事件 + 玩家同一目标的动作 |
| 世界 | 每次 `structuredClone(STARTER_TOWN.world)`，`clock = 0`，不应用 verdict（各条独立） |
| 上下文 | 与 `runBeat` 同构：场景句 + `describeLedger(..., {withIds:true})` + `contextOf(scene, player)` |
| 骨架文本 | 固定模板（**不是**模型生成的），填肉不在本探针范围 |
| 模型 | `opencode-go/deepseek-v4.1-flash`，独立 `sessionId` |
| 记录 | `ok` / `deltas` / `duration` / `reason` / 耗时，落 `data/probe-storylet/probe.jsonl`（`data/` 不入库） |
| 复现 | `node --experimental-strip-types scripts/probe-storylet.ts`；重算汇总用 `--replay`（不重复调用） |

三个骨架都只读账本、效果目标都落在已有键上：

| storylet | actor | 条件（只读） | 骨架文本 | 期望效果 |
| :--- | :--- | :--- | :--- | :--- |
| `lamp-gutters` | `lamp` | `phys.lamp.lit === true` | 灶膛里爆出一粒火星，落在灯芯上，灯焰跳了两下，然后灭了。 | `phys lamp lit=false` |
| `door-blown-open` | `door` | `phys.door.closed === true` | 风从门缝里挤进来，把没插紧的门闩顶开，门自己撞在墙上。 | `phys door closed=false` |
| `cellar-hatch-lifts` | `cellar` | `phys.cellar.open === false` | 地窖盖板被下面的水汽顶起一条缝，木边卡在半开的位置。 | `phys cellar open=true` |

## 3. 结果

| 臂 | storylet | 判定 | deltas | duration | 裁判给的理由（原文） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| world | `lamp-gutters` | `no` | — | 1m | 酒馆里没有点着的灶膛，也没人靠近拨弄灯，灯焰不会自己爆火星灭掉；此刻灯仍亮着。 |
| world | `door-blown-open` | `ok` | `phys door.closed=false` | 1m | 门只是合着，并未上闩；风从门缝里灌进来顶开门闩，门被吹开撞在墙上。 |
| world | `cellar-hatch-lifts` | `no` | — | 1m | 地窖盖板从内侧扣死，地窖下并无积水或水汽可顶，无人触碰，盖板纹丝不动。 |
| competition | `lamp-gutters` | 世界 `no` / 玩家 `ok` | 玩家 `phys lamp.lit=false` | 1m | 灯是死物，不会自己爆火星烧断灯芯；灶膛的火星没有依据落到灯上。 |
| competition | `door-blown-open` | 世界 `no` / 玩家 `ok` | **都为空** | 2m | 你抢在阵风掀起门闩前把手压上去，门仍关着。 |
| competition | `cellar-hatch-lifts` | 世界 `no` / 玩家 `ok` | **都为空** | 1m | 地窖盖板是关死的，没有人打开它，也没有任何东西从下面顶它——水汽顶不开盖板。 |

汇总：`world` 臂 `ok` 33.3%、有 delta 33.3%、空结果 0.0%；竞争臂按事件算，世界落账 0 / 玩家落账 1 / 双方都没落账 2。成本 9 条裁决 54.6s（均 5.9s，基线裁判 22.1s 是因为本探针 context 与 claims 都小），tokens 6285 / 3189，`duration` 全部 1–2 分钟。

## 4. 四条发现

1. **拒的不是身份，是因果。** 两条 `no` 的理由都是"缺前因"（灶膛没点着、地窖下没有积水），没有一条说"实体不能发起事件"。`door` 那条被放行，说明非人 actor 本身合法。
2. **有人竞争时，世界事件 0/3 落账。** 裁判明确写出"灯是死物，不会自己……"，并在门/地窖两例里判玩家成功但 `deltas` 为空（"门仍关着"）。世界事件和玩家的动作抢同一状态时，账本系统性偏向人。
3. **裁判会自造前提来圆场。** `door` 的理由写"并未上闩"，但账本里只有 `closed` / `broken`，没有"闩"。前提只活在这句话里，不进账本——但这句话会喂给旁白，于是正文可能写出账本不支持的事实（"闩" → 后续 `move` 判定与文本冲突）。这是"文本不是证据"的一个新漏点。
4. **成本可忽略。** 抽卡一次纯函数、0 调用；放行的代价只有裁判原本就要付的那一次。`duration` 全部 1–2 分钟，没有为了让世界动起来而引入时长表。

## 5. 由结果反推的约束（待审）

| # | 约束 | 依据 |
| :--- | :--- | :--- |
| 1 | 条件要对**因**，不是只对**果**：放行一条需要"灶膛点着"，而不只是"灯亮着" | 发现 1；`phys` 里目前没有这些键，缺的键要手工补 |
| 2 | 抽卡只在**本拍无人主张**时触发 | 发现 2；这条同时把 `runBeat` 里"没有主张就早退"的位置变成兜底 |
| 3 | 效果只能落在**账本已有键**上；文本不得引入账本没有的前提 | 发现 3 |
| 4 | 填肉不得自造前因（"不知哪来的火星"），否则等于替裁判编前提 | 发现 3 的推论，未验证 |

约束 1 的代价最大：它把"写条件"变成"把因果链建模进 `phys` 键表"，而键表是手工维护、且规定"出现无法一句话解释的键立即删"（[../design/backlog.md](../design/backlog.md)）。三个骨架里有两个死在这一点上。

## 6. 不能宣称什么

- 样本是 3 个 storylet、单模型、每条一次采样；`no_rate`、接受率在这里没有统计意义。
- 没测：条件求值器、模型填肉、多拍进度、抽卡结果落 journal 与 replay、把抽卡摊到 20 拍后的成本与空转率变化。
- 竞争臂的"玩家 ok 但空 delta"不能解读为裁判放水：两条理由都明确说结果没发生。

## 7. 填肉：骨架 → 1 到 2 句（3 条）

`scripts/probe-storylet-fill.ts`，3 次真实调用（`narration` 角色，9.6s，855 / 465 tokens）。硬检查用的是仓库现成的 `findAbsoluteTime` 与 id 正则。

| 骨架 | 成文 | 绝对时间 | id 泄漏 | 评 |
| :--- | :--- | :--- | :--- | :--- |
| `lamp-dies` | 灶膛里爆出一粒火星，落在灯芯上，灯焰跳了两下，然后灭了。酒馆里暗下来，外面的雨还在下。 | 无 | 无 | 加了"酒馆里暗下来"，与 `phys lamp.lit=false` 一致 |
| `door-blown` | 风从门缝里挤进来，把没插到底的门闩顶开，门板自己撞在墙上。 | 无 | 无 | 只把骨架的"没插紧"改成前因里的"没插到底"，几乎照抄 |
| `cellar-lifts` | 地窖盖板被下面的水汽顶起一条缝，木边卡在半开的位置，缝里透出湿气。 | 无 | 无 | 新增"缝里透出湿气"，等于把前因又说了一遍 |

结论：**硬检查全过，软规则被破。** 单次探针里模型倾向于近乎照抄（因为它被要求"不引入新前提"）；但 A/B 真实运行里，同样的提示词写出了两类违规（见 §8）：替人物做动作、自造物理细节。

## 8. 10 拍 A/B：加不加世界事件

两条臂各自从 `STARTER_TOWN` 原始世界起跑，10 条相同的玩家输入，独立 store；一条只有玩家与人物，一条每拍抽 0 到 1 条世界事件（前因只读 `facts`，无因不抽，抽中后填肉）。模型同一条串。

| 指标 | base | storylet |
| :--- | :--- | :--- |
| 落 journal 的拍 | 10 | **9**（1 拍裁判调用失败 → 设计内的"无进展"降级） |
| 空转拍（整拍账本没动） | 3 / 10 | 1 / 9 |
| claims | 50（5.00/拍） | 52（5.78/拍） |
| 裁决 / `no_rate` | 50 / 8.0% | 52 / 13.5% |
| 空结果占比 | 64.0% | 55.8% |
| 写操作 | 17（fact 11 / rel 1 / know 2 / transfer 2 / consume 1） | 20（fact 12 / rel 2 / **phys 1** / transfer 2 / consume 1 / know 2） |
| `facts/beat` | 1.10 | 1.33 |
| 抽卡 | — | 尝试 10 · 命中 8 · **落账 1 / 7** |
| 墙钟 | 400s | 486s（+21%） |
| narration 调用 | 10 | 17（8 次填肉 + 9 次旁白） |
| 裁判均耗时 | 17.6s | 23.4s |

两臂 journal 都能 `replay` 出账本与人物记忆（`phys` 只差 `door.closed`，就是那条被放行的世界事件）。

四条发现：

1. **池退化成一张牌。** `cellar-lifts` 连抽 6 次：它的条件是 `phys.cellar.open === false`，被拒之后条件仍然成立，于是每拍重抽，每次还付一次填肉调用。**没有冷却就没有"抽卡"，只有"复读"。**
2. **关键词前因是假前因。** 给 `cellar-lifts` 配的是 `地窖 / 水 / 账本 / 柜台`，A/B 里 `账本` 命中了一条关于账本的 fact，于是裁判看到的是"账本的事"配"地窖冒水汽"，六次全判 `no`（"没有热源""压实木板顶不开"）。
3. **填肉在替人做决定、自造细节。** 同一批骨骼的第一条成文是"地窖盖板……缝里往外冒白气。**格蕾妮退到门边站定，一手按着腰上的钥匙串**"——世界事件的 actor 是 `cellar`，正文却给格蕾妮加了动作；另一条写"格蕾妮按着钥匙串的手停在腰上"。裁判随后把这些细节当成判断对象（"没有可解释这股水汽的热源"）。
4. **成本是实的，收益是单点的。** +21% 墙钟、6 次无效裁决、`facts/beat` 从 1.10 升到 1.33；换来 1 条 `phys` 与空转拍从 3 降到 1。

结论：**这一版 A骨B肉 净收益为负，但失败点是实现级的，不是架构级的。** 四个点都能在池里改掉：冷却（同骨架 N 拍内不再抽）、前因必须能解释事件（不是关键词命中）、填肉禁写人与禁造细节、骨架的物理可信度由作者负责（"水汽顶开压实木板"这种就不该进池）。改完之前不要跑 20 拍——只会把"一张牌连抽 12 次"放大。

## 9. 不能宣称什么（§7 §8 追加）

- 每臂只有 1 次采样，且两条臂的模型轨迹不同（同一句输入下人物的说法不同）；"空转 3→1"**不是**可比结论。
- storylet 臂少了一拍：一次裁判调用重试后仍失败，按设计整拍无进展。`no_rate`、`claims/拍` 的分母因此不同。
- `+21%` 墙钟里约 8 次是填肉调用；去掉填肉后抽卡本身的成本还没有单独测。
- 判 `no` 的 6 条不能当作"世界事件不可行"：它们大多死于 §8 发现 1–3，而不是死于"非人 actor"。

## 10. v2：冷却 + 紧前因 + 模板文本（10 拍 A/B）

只改池，不改分层：同一骨架 6 拍内不重抽；前因关键词收窄到"事件自己的物理施动者"（`风 / 雨 / 门`），删掉被误配的 `账本 / 柜台` 与物理上不成立的"水汽顶开盖板"；抽卡不调模型，直接给模板文本。两条骨架构成一条可验证的链：门被风吹开 → 有穿堂风 → 灯灭。

| 指标 | base | storylet |
| :--- | :--- | :--- |
| 空转拍（整拍账本没动） | 2 / 10 | 3 / 10 |
| claims | 50（5.00/拍） | 52（5.20/拍） |
| 裁决 / `no_rate` | 50 / 12.0% | 52 / **5.8%** |
| 空结果占比 | 58.0% | 71.2% |
| 写操作 | 17（fact 13 / transfer 2 / consume 1 / rel 1） | 13（fact 9 / transfer 1 / consume 1 / **phys 2**） |
| `facts/beat` | 1.30 | 0.90 |
| 抽卡 | — | 尝试 10 · 命中 2（`door-blown`、`lamp-dies`）· 冷却跳过 2 · **落账 2 / 2** |
| 墙钟 | 418s | 408s |
| 调用数 | cognition 40 / referee 10 / narration 10 | 同左（抽卡不再调用模型） |

四条发现：

1. **三个修正全部生效。** 世界事件落账率从 1/7 升到 **2/2**；冷却把"连抽 6 次"压到 2 次；模板文本让抽卡的边际成本变成 0（墙钟 408s vs 418s）。
2. **空转拍没降。** 两张牌落在第 7、8 拍，而这两拍本来就有 2 条 delta——世界事件加在了"已经有事发生"的拍上，只多了一条 `phys`，没填掉任何一个死拍。
3. **死拍的位置说明触发条件与目标是错位的。** 两臂的死拍都在第 2–3 拍（最早，账本里还没有任何 fact）和最后一拍（睡醒，没人有主张）。"无因不抽"让抽卡只能**事后跟风**，而它要填的恰恰是**事前的静**。
4. **`no_rate` 5.8% 低于健康区（15–40%），空结果升到 71.2%。** 单样本不足以定性，但形态值得盯：裁判更容易判"成立但不改账本"。

结论：**机制通了，触发条件没通。** 冷却、前因一致性、零成本这三项留用；"前因只读 `facts`"这条在没有历史的前几拍等于禁用抽卡，正好错过它最该出手的地方。

## 11. 不能宣称什么（§10）

- 仍是一臂一次采样，两臂的对话轨迹不同；`空结果 58% → 71%` 与 `no_rate 12% → 5.8%` 不能当因果。
- 只有 2 次抽中，落账率 2/2 的置信区间很宽。
- 没测：环境类前因（canon）、20 拍尺度、折场后池状态、同一骨架的更长短冷却。

## 12. v3：两级前因（ambient 环境 / facts 后果）10 拍 A/B

改动：`World.ambient`（只读世界根常量，与 `places` 同性质）；池子按 tier 分流——环境骨架的前因读 `ambient`，后果骨架的前因读 `facts`，两者不许互借；`ambient` 缺键 = 不满足，不默认通过。`starter-town` 声明 `{ weather: 'storm', night: true }`，即已有的"外面的雨没停"变成可查询的世界常态。

| 指标 | base | storylet |
| :--- | :--- | :--- |
| 空转拍 | 3 / 10 | **1 / 10** |
| claims | 50（5.00/拍） | 53（5.30/拍） |
| 裁决 / `no_rate` | 50 / 8.0% | 53 / 11.3% |
| 空结果占比 | 66.0% | 50.9% |
| 写操作 | 17（fact 12 / rel 1 / transfer 2 / know 1 / consume 1） | 24（fact 15 / **phys 3** / transfer 2 / consume 1 / know 2 / rel 1） |
| `facts/beat` | 1.20 | 1.50 |
| 抽卡 | — | 尝试 10 · 命中 3（`door-blown`、`lamp-dies`、`door-splinter`）· **落账 3 / 3** |
| 墙钟 | 536s | 583s（+9%） |
| 落 journal 的拍 | 10 | 10 |

四条发现：

1. **第一条世界事件发生在第 1 拍（clock 0）**，正是前两版抽不出东西的那一拍，也是 base 臂里没有对应变化的拍。它把第 1 拍从"只有话"变成"账本动了"（`phys door.closed=false`）。
2. **去掉采样噪声后，净效果是 1 个死拍。** base 的死拍是 2、3、9；storylet 的死拍只剩 3。把世界事件贡献的那条 `phys` 拿掉，storylet 仍会有第 1 拍是死拍 → 真实净效果是 1，不是 2。"空转 3→1"不能直接当结论。
3. **竞争裁决这次是"风胜"。** 同一拍玩家说"我推门进去"，裁判判 `no`，理由写明"与 w0 互斥，判风胜"。这与第一次探针竞争臂 0/3 的结果相反——说明**世界事件和玩家主张谁赢是不稳定的**，不能靠运气。更值得注意的是玩家体验：他的动作被一件世界事件顶掉了。
4. **抽卡在认知之后，本拍没人看得见刚发生的事。** 安那句"门是闩着的。你是推开的，还是它自己开的"是巧合，不是反应——认知调用在抽卡之前发起。

## 13. 不能宣称什么（§12）

- 仍是一臂一次采样；`no_rate`、`空结果`、`facts/beat` 的差异都在噪声量级（`facts/beat` 升到 1.50 是这轮对话多，不是世界事件写了 fact）。
- 落账 3/3 只说明"这三条"能被接受，不说明池子整体接受率高。
- 没测：抽卡移到认知之前的排序、世界事件与玩家主张的优先级规则、多轮重复下的稳定性、20 拍尺度。

## 14. v4：抽卡避让（关键词）——失败，且顺带证伪了 10 拍 A/B 的分辨率

改动：骨架声明 `avoidKeys`，本拍任一 claim 文本提到该词就让路（`门` / `灯`），目的是不让世界事件顶掉玩家的动作。

结果：**10 拍 0 命中**，世界事件一条都没抽出来。

原因很清楚：50 条 claim 里有 **23 条提到"门"**（安："门是闩着的。你是推开的，还是它自己开的"；科迪："这店里的规矩是入夜就闩门"），10 个拍里每一拍都至少有一条。避让把整池关掉了。`灯` 同理（7 条），只是灯那张本来要等门先开。

更重要的附带结果：这一跑等价于 base（0 命中），空转拍是 **5 / 10**；而 base v3 是 **3 / 10**。**同一配置的两次采样差 2 个死拍。** 也就是说 §12 里 storylet 的 1 死拍不是"降了 2"，而是落在这 3–5 的噪声带里——v3 的"空转 3→1"不能作为收益证据。

结论：

1. **关键词避让不可用。** 这已经是第三次用关键词做因果相关判断（第一次 `账本`→`地窖`、第二次 canon 方案），三次都错。
2. **10 拍单臂单次 A/B 测不出这个效应。** 噪声带（±2 死拍）和预期效应（1–2 死拍）同量级。要判断收益，必须同条件重复≥3 次或拉到 20 拍，并报分布而不是单点。

## 15. 不能宣称什么（§14）

- 不能说"避让不好"：只有一种实现（子串匹配）被证伪，按 `actor` 或结构化目标避让还没试。
- 不能说"v3 有效"：它的单点结果落在噪声带内。
