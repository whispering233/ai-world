## 3. 失败与降级

- `to` 未命中/重名/是玩家自己 → 不聚焦，本拍按所有人，notes 写“聚焦失败（本拍按所有人结算）：…”。
- 目标在请求后被移走 → 服务端按当前地点重新解析，不聚焦；Web 的 `effectiveTarget` 也会把离场目标回成“所有人”。
- 裁判失败时聚焦失败的 note 仍在错误信息里，不静默消失。
- 旧 journal 没有 `claim.to` 时，`playerTo` 缺省；不会回退显示实体 id。
- “等一会儿”始终对所有人（文案是“看看他们怎么说”），不继承已选中的单人目标；自由输入才带 `to`。

## 4. 结论

- 聚焦链路成立：显示名解析 → 只叫玩家+目标 → claim.to 落 journal → 投影回显示名 → UI 前缀。
- 默认路径未回归；测试 351 通过，typecheck/build 绿。
- 客户端没有拿到 id；作者壳的 claim 列表现在显示原始 `to` id（作者视角允许）。

## 5. 风险

- 没有跑“12 拍全部定向”的 smoke；定向效果由一次浏览器拍 + 单元测试覆盖，样本小。
- 目标按显示名唯一匹配；内容里出现重名时只能退回“所有人”。
- 目标 chips 是单选语义，但显示名重复时两个 chip 会同时选中；服务端会拒绝聚焦并记 note。
- `to:null` 被路由当成非法（400），只有“省略字段”表示所有人；客户端不会发 null。
- 定向后其他人物不产生 claim，也可能让场景显得安静；这是 #48 的取舍。
